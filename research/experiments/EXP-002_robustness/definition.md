# EXP-002 — Robustness of a local RAG pipeline to controlled perturbations

Status: defined 2026-11-19, **before any EXP-002 run**. The paraphrase set was generated and
reviewed before this definition was written; no answers to paraphrased questions had been
generated at that point.

## Research question

**RQ5 — Robustness.** How sensitive are answers and verdicts to controlled changes in prompts,
context ordering, irrelevant context and question wording, compared with the variation that
occurs when nothing is changed?

EXP-001 already covered two other RQ5 factors and is not repeated here: retrieval depth
(top-1 vs top-3) and temperature (0 vs 0.8).

## Hypotheses (stated before the run)

The project's working hypothesis for RQ5 was: *"Paraphrasing questions or reordering context changes
verdicts on < 10% of cases."* Per arm:

- **H1 (context order):** reversing the order of the three retrieved passages changes the LLM-judge
  verdict on < 10% of questions, and the net change in judge-correct rate is not significant
  (exact McNemar test, p ≥ 0.05). With only three short passages, position effects of the kind
  reported for long contexts (Liu et al., 2023) should be small.
- **H2 (irrelevant passage):** adding the corpus passage least similar to the question before the
  retrieved passages changes the judge verdict on < 10% of questions. An off-topic passage should
  be easy to ignore. Shi et al. (2023) report distraction mainly with *related* irrelevant context.
- **H3 (question wording):** rewording the question changes the judge verdict on **more** questions
  than H1 or H2 (expected ≥ 10%), because wording changes both retrieval and generation.
  Retrieval Hit@3 also changes for some questions.
- **H4 (prompt template):** replacing the short-answer instruction (`concise_v1`) with the free-form
  template (`default_v1`) lowers exact match and SQuAD EM substantially (≥ 15 points), because
  answers become sentences. The judge-correct rate changes by < 5 points. Lexical metrics would
  then measure answer format, not correctness.

## Design

All arms use qwen3:4b-instruct with top-3 retrieval, temperature 0, seed 42 and `max_tokens = 64`.
Each arm changes **one** factor relative to the baseline.

| Arm | Change vs baseline | Runs |
|---|---|---|
| `base` | none: concise_v1 template, ranked passage order, original questions | 2 (noise floor) |
| `reversed` | `context_order = reversed`: best passage last | 1 |
| `distractor` | `distractor_chunks = 1`: least-similar corpus chunk placed first | 1 |
| `paraphrase` | each question replaced by its frozen paraphrase | 1 |
| `freeform` | `prompt_template_id = default_v1` | 1 |

**Controlled variables:** generator, judge (qwen3:4b-instruct, T = 0, seed 42, JSON format; same
rubrics as EXP-001), embedding model and prefixes, corpus and chunking (800/100, 378 chunks), gold
answers and `relevant_chunk_ids`, evaluators (exact_match, squad_match, llm_judge,
llm_faithfulness_judge), Ollama version and model digests. All runs are executed in one session
with the same warm-up procedure as EXP-001.

**Perturbation implementation.** The perturbations change only the prompt.
- `reversed` and `distractor` do not change `retrieved_chunks`, so retrieval metrics are
  identical to the baseline by construction. This is checked, not assumed.
- The injected passage is recorded separately (`injected_chunks`).
- The faithfulness judge sees the retrieved passages, not the injected one.
- Passages are numbered by their position in the prompt, so the model is not told the retrieval rank.

**Paraphrases.** One rewording per question, generated by qwen3:4b-instruct
(`scripts/build_paraphrase_set.py`) and frozen in
`data/benchmarks/squad_v1_1_dev_subset_v1_paraphrases_v1.json`.
- Automatic checks: no answer leak, still a question, length ratio. 2 of 60 are length outliers.
- Meaning review: **by the AI assistant, not a human**. Result: 54 same meaning, 3 minor shifts,
  3 changed meaning (see the file).
- The paraphraser is the same model as the generator. Its rewordings may therefore be easier for it
  than a human's would be (limitation).

**Dependent variables:**
- per-evaluator pass rate;
- per-question verdict flips relative to `base` run 1, split by direction;
- identical-output rate;
- rule-based diagnosis category consistency (`diagnostics.robustness.summarize_robustness`);
- Hit@3, Recall@3, Precision@3 and MRR;
- generation latency and tokens.

## Analysis plan (fixed before the run)

- **Primary measure per arm:** the share of questions whose LLM-judge verdict differs from `base`
  run 1. It is compared with the **noise floor**: the share that differs between `base` run 1 and
  `base` run 2 with nothing changed. A perturbation effect is reported only to the extent that it
  exceeds the noise floor.
- **Net effect:** exact McNemar test on the paired 2×2 table (judge verdict, `base` run 1 vs arm),
  α = 0.05, with no correction (four planned contrasts). Wilson 95% intervals for rates.
- **Paraphrase arm:**
  - **Primary analysis:** excludes the 3 paraphrases reviewed as `meaning_changed` (n = 57).
  - **Sensitivity analysis:** all 60.
- **Exclusions:** questions where either compared run lacks a SUCCESS judge verdict are excluded and
  counted.
- **Sample size:** n = 60 (57). A flip rate of 10% has a Wilson interval of about ±8 points, so only
  large differences between arms can be distinguished. Differences below about 10 points are
  reported as not distinguishable.

## Threats to validity

- **Judge:** the judge is the generator's own model family (self-preference). Its validity against
  humans is unmeasured; see the human-annotation tooling in `research/annotation/`.
- **Generalization:** one model, one dataset, 60 questions, a single paraphrase per question, and one
  distractor type (the least similar passage). These results do not generalize to long contexts or
  to adversarial distractors.
- **Determinism:** temperature 0 is not fully deterministic on this server (EXP-001: 57/60 identical
  outputs). This is why the noise floor is measured in the same session.
